# Проверки плейбука

Три набора проверок на Node. Нужны, чтобы правки в схеме, в слое данных и в интерфейсе
не ломали доставку изменений от капитана к игрокам.

```bash
cd tests
npm install
npm run all      # или по отдельности: npm run schema / client / ui
```

| Файл | Что проверяет | Как |
|---|---|---|
| `test.mjs` | схема базы: таблицы, RLS, серверная проверка PIN, изоляция команд, realtime-публикация, политики хранилища, лимит журнала | поднимает настоящий Postgres в WASM (PGlite), `stubs.sql` добавляет заглушки Supabase (`auth.uid()`, `storage`, роли) |
| `test-client.mjs` | слой данных `db.js`: включение облака по ключам, порядок списков (`pos`), чат (отправка INSERT'ом, пустые и длинные сообщения, лимит ленты, удаление, права, realtime, ошибка отправки), офлайн-поведение, самодиагностика, защита от `service_role` key | подменяет Supabase-клиент фейком, который ведёт себя как PostgREST + Realtime |
| `test-ui.mjs` | приложение целиком: вход и создание команды, обзор, навигация, тактики и фильтры, доска (инструменты, отмена/повтор, зум, сохранение, очистка, полный экран), панель игрока, видео и YouTube-плеер, CRUD тактик/игроков/карт/материалов/видео, роли и язык, PIN, экспорт и импорт, чат, права игрока, поиск, мобильная раскладка, перезагрузка | поднимает `index.html` в jsdom и выполняет реальные скрипты |

Ожидаемый результат: `28 passed, 0 failed`, `53 passed, 0 failed`, `147 passed, 0 failed`.

## Что здесь ловилось (чтобы не потерялось снова)

- `trim_activity` не обрезал журнал: удаление выполнялось от имени игрока и блокировалось RLS.
- Новые строки в облаке получали `pos = 0` — порядок тактик у капитана и у игроков расходился.
- Раздел «Управление» падал на привязке обработчиков к кнопкам экспорта/импорта,
  которых не было в разметке: вместе с ними отваливались «Выйти из команды» и «Удалить команду».
- **Чат в облаке не отправлялся вовсе**: сообщение уходило с клиентским `id`, адаптер выбирал
  `update` несуществующей строки и падал на `.single()`. Теперь сообщения пишутся только
  через `sendMessage()` (INSERT) — и в облаке, и локально.
- **Лента чата теряла последние сообщения**: список читался `order(ts asc).limit(400)`,
  то есть брались самые старые. Теперь `desc + limit` и разворот на клиенте.
- Инструменты доски не реагировали на клик: обработчики навешивались на результат
  `querySelector` вместо `querySelectorAll`.
- Режим «на весь экран» прятал шапку и меню и не возвращал их при уходе с экрана тактики.
- Импорт копии команды пересоздавал строки с новыми `id` и рвал связи: тактики теряли карту,
  задачи и гранаты — игрока. Теперь идентификаторы перепривязываются при загрузке.
- PIN капитана, равный PIN команды, позволял любому игроку повысить себя до капитана —
  закрыто и в приложении, и в `team_set_pin`.
- Старый `sw.js` кэшировал файлы: после обновления возвращающийся пользователь видел
  прежнюю вёрстку. Service worker удалён, а `index.html` снимает чужие регистрации
  и чистит Cache Storage.
- Удаление игрока оставляло в тактиках `playerId` несуществующего игрока — токены
  рисовались со знаком «?» вместо номера. Привязки теперь снимаются при удалении.

## Чего проверки не покрывают

- Настоящее облако Supabase: из песочницы проект недоступен, поэтому облачный путь чата
  проверяется на подставном клиенте, а не на живой базе. Подключение к своему проекту
  проверяйте кнопкой «Проверить связь» в приложении.
- Визуальную сторону (шрифты, отступы, поведение на реальном телефоне): браузер в окружении
  разработки не устанавливался, поэтому раскладка проверяется по разметке и CSS, а глазами —
  на живом сервере (`python3 -m http.server 8000`).

Проверки запускаются только на компьютере разработчика: в репозиторий попадают
только сами тесты, `node_modules` не коммитится.
