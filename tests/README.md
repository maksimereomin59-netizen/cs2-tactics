# Проверки плейбука

Три набора проверок на Node. Нужны, чтобы правки в схеме и в слое синхронизации
не ломали доставку изменений от капитана к игрокам.

```bash
cd tests
npm install
npm run all
```

| Файл | Что проверяет | Как |
|---|---|---|
| `test.mjs` | схема базы: таблицы, RLS, серверная проверка PIN, изоляция команд, realtime-публикация, лимит журнала | поднимает настоящий Postgres в WASM (PGlite), `stubs.sql` добавляет заглушки Supabase (`auth.uid()`, `storage`, роли) |
| `test-client.mjs` | слой данных `db.js`: включение облака по ключам, порядок списков (`pos`), обновление по realtime, офлайн-поведение, самодиагностика, защита от `service_role` key | подменяет Supabase-клиент фейком, который ведёт себя как PostgREST + Realtime |
| `test-ui.mjs` | приложение целиком: загрузка скриптов, создание команды, раздел «Управление», кнопка «Проверить связь», выход из команды | поднимает `index.html` в jsdom и выполняет реальные скрипты |

Ожидаемый результат: `28 passed, 0 failed`, `34 passed, 0 failed`, `15 passed, 0 failed`.

## Что здесь ловилось (чтобы не потерялось снова)

- `trim_activity` не обрезал журнал: удаление выполнялось от имени игрока и блокировалось RLS.
- Новые строки в облаке получали `pos = 0` — порядок тактик у капитана и у игроков расходился.
- Раздел «Управление» падал на привязке обработчиков к кнопкам экспорта/импорта,
  которых не было в разметке: вместе с ними отваливались «Выйти из команды» и «Удалить команду».

Проверки запускаются только на компьютере разработчика: в репозиторий попадают
только сами тесты, `node_modules` не коммитится.
