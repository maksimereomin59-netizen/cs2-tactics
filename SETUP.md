# Подключение облака (Supabase) — правки капитана долетают игрокам

Сейчас сайт работает **локально на каждом устройстве**: капитан правит у себя,
игроки этого не видят. После подключения Supabase любая правка капитана
появляется у всех игроков сама, без перезагрузки (в шапке — статус соединения
и всплывающее «Обновлено»).

Разовая настройка ≈ 10 минут. Платить не нужно: бесплатного тарифа хватает команде
(до 50 000 активных устройств в месяц, 500 МБ базы).

Нужен только аккаунт Supabase — создаётся по e-mail или через GitHub.

---

## Шаг 1. Создайте проект

1. Откройте https://supabase.com → **Start your project** → войдите.
2. **New project**: имя любое (например `cs2-playbook`), пароль базы — сгенерируйте
   и **сохраните его в менеджере паролей** (он нужен только для администрирования).
3. **Region** — чем ближе к команде, тем быстрее realtime. Для России обычно
   `Central EU (Frankfurt)`.
4. Создайте и подождите 1–2 минуты, пока база поднимется.

## Шаг 2. Включите анонимный вход (обязательно)

Без этого шага вход в команду не заработает: приложение использует анонимные
сессии, чтобы база знала, какие данные отдавать устройству.

1. В проекте: **Authentication → Sign In / Up**.
2. Включите **Allow anonymous sign-ins** и сохраните.

> Дополнительно можно выключить «Confirm email»/email-провайдер, чтобы поле
> «Email» не мешало: приложение вход по e-mail не использует.

## Шаг 3. Примените схему базы

1. **SQL Editor → New query**.
2. Откройте в репозитории файл `supabase-schema.sql`, скопируйте его **целиком**
   и вставьте в редактор.
3. Нажмите **Run**. В результате должно быть `Success. No rows returned`.

Схема создаёт 8 таблиц, защиту построчно (RLS), серверную проверку PIN,
подписки realtime и корзину для файлов команды.

Проверить, что всё на месте: **Table Editor** — должны быть `teams`, `memberships`,
`players`, `maps`, `tactics`, `materials`, `templates`, `activity`.

> Схему можно запускать повторно — она написана идемпотентно и ничего не удалит.
> Так же обновляйте её после изменений в репозитории.

## Шаг 4. Вставьте ключи проекта

1. В Supabase: **Settings → API**.
2. Скопируйте **Project URL** и **anon public** key.
3. В репозитории откройте файл `supabase-config.js` и замените заглушки:

   ```js
   window.SUPABASE_CONFIG = {
     url: "https://ваш-проект.supabase.co",
     anonKey: "eyJhbGciOi…"
   };
   ```

4. Закоммитьте и запушьте в `main`. GitHub Pages обновит сайт за 1–2 минуты.

**Нужен именно `anon public` key.** Он публичный по дизайну Supabase: доступ к данным
закрыт RLS-политиками, а PIN проверяется функцией на сервере, не в браузере.
Секретный `service_role` key вставлять нельзя — приложение его отклонит и напишет
об этом, чтобы ключ не утёк на публичный сайт.

## Шаг 5. Проверьте связь прямо в приложении

1. Откройте сайт, войдите (название команды + PIN).
2. **Управление → Облако → «Проверить связь»**.

Проверка идёт по шагам и показывает, что именно не так, с готовой подсказкой:

| Пункт | Что значит |
|---|---|
| Ключи проекта | `supabase-config.js` заполнен, URL распознан |
| Подключение к базе | облачный режим включился (не local) |
| Анонимный вход | включён «Allow anonymous sign-ins» |
| Таблицы базы | применён `supabase-schema.sql` |
| Серверная проверка PIN | серверные функции входа доступны |
| Хранилище файлов | создана корзина `team-files` |
| Живые обновления (Realtime) | канал подписан — правки прилетят сами |
| Чтение / запись правок | права роли работают (запись — у капитана) |

Нужно, чтобы все пункты были с ✓. Если что-то с ✕ — читайте подсказку под пунктом:
там написано, что именно исправить.

## Шаг 6. Проверьте на двух устройствах

1. ПК: войдите капитаном, **Управление → Ввести PIN капитана**.
2. Телефон: войдите тем же названием команды и PIN игрока.
3. На ПК измените тактику (например, перетащите маркер или добавьте блок).
4. На телефоне изменение появляется **само, без перезагрузки**, с пометкой «Обновлено».

Если так — облако подключено, дальше вся работа синхронна.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| В шапке «Локальный режим», в Управлении «облако не подключено» | `supabase-config.js` не заполнен или не закоммичен: Проверка связи укажет пункт «Ключи проекта» |
| «Облако недоступно, включён локальный режим» | чаще всего выключен **Allow anonymous sign-ins** (шаг 2) или неверный URL/ключ |
| Проверка связи: «нет доступа: tactics, players…» | схема не применена или применена частично — запустите `supabase-schema.sql` целиком (шаг 3) |
| Правки не появляются у игроков, хотя всё ✓ до «Realtime» | проект на паузе (Free: реактивируйте в Dashboard) или таблицы не попали в публикацию — перезапустите схему (шаг 3) |
| Игрок видит «Только капитан может изменять» | это норма: игроки не пишут в базу, они получают правки капитана |
| Потерян PIN команды | смена только из приложения, когда капитан залогинен: **Управление → Сменить PIN команды**. Если доступ потерян полностью — новый PIN задаётся в SQL Editor от `postgres` |
| Хочу откатить всё и снова локально | очистите `supabase-config.js` (верните заглушки) или нажмите «Сбросить» в окне «Облако» |

## Как это устроено (и почему безопасно)

- **Вход**: название команды + PIN. PIN сверяет серверная функция `team_login`,
  хеши и соли в браузер не отдаются.
- **Устройство** получает анонимную auth-сессию и привязку к команде в `memberships`.
- **Роли**: игрок только читает, писать может только капитан — это политики RLS
  в базе, а не запрет в интерфейсе. Роль капитана подтверждается его PIN
  (`claim_captain`).
- **Realtime**: клиент подписан на изменения таблиц своей команды; чужие команды
  физически не могут прочитать ваши данные.
- **Офлайн**: последний загруженный плейбук кэшируется на устройстве и открывается
  без интернета; запись при отсутствии связи отклоняется с понятным сообщением,
  а не пропадает молча.

## Что делать после изменений в репозитории

- Меняли `supabase-schema.sql` → повторно примените его в SQL Editor (шаг 3).
- Меняли только `app.js` / `db.js` / `styles.css` → достаточно пуша в `main`.
