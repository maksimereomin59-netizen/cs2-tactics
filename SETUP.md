# Подключение облачной синхронизации (Supabase)

Без этого шага плейбук работает локально на каждом устройстве:
данные хранятся в браузере, синхронизации между устройствами нет.
Чтобы капитан правил с компьютера, а игроки видели изменения на телефоне онлайн,
подключите бесплатный Supabase-проект. Это делается один раз, минут за 10.

## Шаг 1. Создайте проект

1. Откройте https://supabase.com и создайте бесплатный проект (Free tier достаточно).
2. Дождитесь запуска базы.

## Шаг 2. Включите анонимный вход

1. В проекте: **Authentication → Sign In / Up**.
2. Включите **Allow anonymous sign-ins**.
3. Сохраните.

## Шаг 3. Примените схему базы

1. Откройте **SQL Editor → New query**.
2. Вставьте целиком файл `supabase-schema.sql` из этого репозитория.
3. Нажмите **Run**. Ошибок быть не должно.

Схема создаёт таблицы команд, игроков, карт, тактик, материалов и журнала,
включает Row Level Security (команда А физически не может прочитать данные
команды Б), серверную проверку PIN через RPC и Realtime-подписки.

## Шаг 4. Подключите сайт к проекту

1. В проекте: **Settings → API**. Скопируйте **Project URL** и **anon public key**.
2. В репозитории скопируйте `supabase-config.example.js` в `supabase-config.js`.
3. Вставьте свои значения:
   ```js
   window.SUPABASE_CONFIG = {
     url: "https://xxxx.supabase.co",
     anonKey: "ваш_anon_key"
   };
   ```
4. Закоммитьте и запушьте — GitHub Pages подхватит изменения за пару минут.

Anon-ключ публичный по дизайну Supabase: доступ к данным всё равно закрыт
RLS-политиками, а PIN проверяется серверной функцией, а не в браузере.

## Шаг 5. Проверьте

1. Откройте сайт на ПК и на телефоне, войдите в одну команду.
2. На ПК (капитан) измените тактику.
3. На телефоне изменение появляется само, без перезагрузки, с пометкой «Обновлено».

## Как это устроено

- Вход: название команды + PIN. PIN сверяется серверной функцией `team_login`,
  в браузер хеши не отдаются.
- Каждое устройство получает анонимную auth-сессию и привязывается к команде
  через таблицу `memberships`.
- Капитан — отдельная роль, подтверждается своим PIN через `claim_captain`.
  Писать в базу разрешено только капитану (RLS), читать — участникам команды.
- Realtime: клиент подписан на изменения таблиц своей команды.
- Офлайн: последний загруженный плейбук кэшируется и доступен для просмотра,
  в шапке виден статус «Нет соединения».

## Частые вопросы

- **Потерян PIN?** Капитан с доступом к Supabase может задать новый через
  SQL Editor: `select team_set_pin('team-uuid', 'team', 'новый-pin')` —
  но функция требует роль капитана в текущей сессии; проще — Service Role
  не нужен: PIN меняется в приложении (Управление → Команда), пока капитан
  залогинен хотя бы на одном устройстве.
- **Не приходит realtime?** Проверьте, что таблицы добавлены в публикацию
  (схема делает это автоматически) и проект не на паузе (Free: реактивация
  в Dashboard).
- **Хранилище файлов:** корзина `team-files` создаётся схемой автоматически,
  загрузки капитана складываются в папку команды.
